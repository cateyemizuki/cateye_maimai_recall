# 麦麦撤回（maimai-recall）

「麦麦撤回」为 MaiBot 机器人提供消息撤回能力：机器人可以按用户要求撤回指定消息，管理员也可以用命令手动撤回。撤回请求通过平台适配器的通用 action 接口交给 QQ 协议端执行；插件会在删除前按 bot 与目标发送者的 QQ 群身份（群聊）或私聊规则预判能否撤回，不能撤回时返回具体原因。

适合在 MaiBot 上部署 QQ 适配器（默认 Napcat 风格 action 接口）、希望由管理员或 LLM 按需撤回消息的服务器管理员。

插件 ID `github.cateye.maimai-recall`，版本 `0.2.0`，类型 `tool`，作者 cateye，MIT 许可。

| 入口 | 作用 |
|---|---|
| `/撤回` 命令 | 引用消息或指定消息 ID，实际撤回 |
| `/撤回调试` 命令 | 只读诊断：显示 bot 与目标用户的群身份及能否撤回的结论 |
| `recall_message` LLM 工具 | 让模型在权限范围内实际撤回；由 `[rules] enable_llm_tool` 控制是否注册 |

## 安装与启用

1. 将整个 `cateye_maimai_recall/` 目录放入 MaiBot 的插件目录（通常为 `plugins/`）。
2. 启动或重启 MaiBot。加载成功时日志会输出「麦麦撤回已加载：…」；若没有读到任何管理员，还会输出「未读取到任何管理员…」的警告。
3. 在宿主插件管理中确认插件已启用。运行配置由 Runner 生成在插件目录的 `config.toml`，该文件已被 `.gitignore` 排除，不要提交。

兼容区间按 `_manifest.json` 声明：宿主 `host_application` 为 `1.0.0` ~ `1.99.99`，SDK 为 `2.5.0` ~ `2.99.99`；`dependencies` 为空，不需要额外声明 Python 依赖；代码使用 `maibot_sdk` 与 `pydantic`。插件声明的能力为 `send.text`、`api.call`、`message.get_by_id`、`message.get_recent`、`config.get`。

撤回、消息查询、bot 账号查询与群身份查询都通过 `[adapter] action_api`（默认 `adapter.napcat.action.call`）调用。适配器/协议端需要支持 `delete_msg`（撤回）、`get_msg`（查询消息发送者/时间/群号）、`get_group_member_info`（查询群身份，请求带 `no_cache=True`）和 `get_login_info`（查询 bot 账号）。换用其他适配器时，把 `[adapter] action_api` 改成对应入口，并确认它能接受这些 action 名与参数；群身份查询里的群号/用户 ID 在不超过 20 位纯数字时会转成整数，以适配 Napcat。

## 配置

运行时配置由宿主在插件目录生成 `config.toml`（不要提交）。字段如下：

| 配置节 | 字段 | 默认值 | 说明 |
|---|---|---|---|
| `[plugin]` | `enabled` | `true` | 插件总开关字段；插件代码不读取它，实际启停由宿主决定 |
| `[plugin]` | `config_version` | `0.2.0` | 配置版本，隐藏并禁用，勿改 |
| `[rules]` | `admin_users` | `[]` | 插件管理员 ID；留空跟随宿主 `plugin.permission`，填写后与宿主名单合并去重。支持单个字符串/数字或列表，条目按纯数字 ID 归一 |
| `[rules]` | `enable_llm_tool` | `true` | 是否注册 `recall_message`；关闭后需重载插件才不再注册，运行期若仍被调用会返回「LLM 撤回工具已关闭。」 |
| `[rules]` | `users_can_recall_bot_messages` | `false` | 允许普通用户撤回本会话内 bot 自己发出的消息（仍受 bot 群身份与时限约束） |
| `[rules]` | `users_can_recall_own_messages` | `false` | 允许普通用户撤回本会话内自己发出的消息（仍受 bot 群身份限制，通常需要 bot 是群主或管理员） |
| `[rules]` | `self_recall_time_limit_sec` | `120` | bot 以普通成员身份撤回自身消息、或在私聊撤回自身消息的时限（秒）；范围 1–86400，按 `>=` 判定，达到时限即拒绝 |
| `[adapter]` | `action_api` | `adapter.napcat.action.call` | 适配器通用 action 入口；撤回、查询与群身份都走它，不要留空 |
| `[limits]` | `cooldown_sec` | `10` | 同一会话两次撤回操作的最小间隔（秒）；范围 0–3600，`0` 为不限制 |

最小配置示例（在生成的 `config.toml` 对应节中修改）：

```toml
[rules]
admin_users = ["10001"]
users_can_recall_bot_messages = true
```

**生效方式**：插件收到自身配置热更新时，会清空 bot 账号缓存与冷却记录，并重新读取管理员名单。`enable_llm_tool` 的注册变化需要重载插件；重载前工具仍可能被调用，处理器会返回「LLM 撤回工具已关闭。」。

**管理员 ID**：宿主 `plugin.permission` 与 `[rules] admin_users` 取并集，按纯数字 ID 去重（`qq:10001` 与 `10001` 视为同一人）；非数字条目会被忽略。宿主名单读取失败时只使用 `admin_users`；两者都为空则没有管理员，加载日志会给出警告。

## 命令

`/撤回` 与 `recall_message` 的可撤回范围与时间窗见「权限规则」。

### `/撤回`

```text
/撤回                 # 撤回当前引用（回复）的消息
/撤回 <消息ID>        # 撤回指定的 QQ 平台消息 ID
```

也可写作 `撤回` 或 `/recall`；`/recall` 必须带斜杠。命令需位于消息末尾，且命令前必须是行首或空白；命令与 ID 之间要有空白；显式 ID 优先于引用目标。显式消息 ID 必须是数字，支持负数（QQ 消息 ID 可能为负）。

- 未引用消息且没有给出 ID 时，回复「请先引用一条消息再使用「/撤回」，或在命令后面附上消息 ID。」。
- 撤回结果（成功或具体失败原因）作为文本发回当前会话；同一会话受 `cooldown_sec` 冷却限制，非管理员的拒绝提示也有独立冷却。
- 目标解析：纯数字（不超过 20 字符）按平台消息 ID 查询，缺失字段用宿主消息库补齐；非数字 ID 视作宿主内部消息 ID，先从消息库换出平台消息 ID。`/撤回` 的显式参数只接受数字，非数字 ID 请用 `recall_message` 的 `message_id`。

示例（群 `123456` 中的管理员 `10001`）：

```text
# 引用一条消息后
/撤回

# 直接指定消息 ID
/撤回 123456789
/撤回 -123456789
```

> 不带斜杠的 `撤回` 也是命令别名，在消息末尾出现时会触发；普通用户仍受权限限制。

### `/撤回调试`

仅管理员可用，只读，不会调用 `delete_msg`，用于排查「机器人明明是管理员/群主却撤不回」。

可用写法：`/撤回调试`、`撤回调试`、`/撤回debug`、`撤回debug`、`/recall_debug`；均可追加数字消息 ID，`/recall_debug` 必须带斜杠。

- 引用一条消息后发送：以被引用消息及其发送者为目标；直接追加消息 ID：以该消息及其发送者为目标；都不给：以命令发送者为目标用户，按当前会话判断。
- 报告包含目标消息/发送者、群号（或「会话：群聊（群号未知）」/「会话：私聊（无群身份）」）、bot 账号与群身份、目标用户与群身份、消息时间与已发出秒数、判定和结论。
- 群身份显示为 `群主（owner）`、`管理员（admin）`、`普通成员（member）`；查询失败显示「未知（查询失败）」，判定可能显示「无法获取机器人的群身份，不能确认撤回权限。」。目标解析失败时仍会展示当前会话的 bot 身份，并给出「结论：无法判定（无法解析目标消息及其发送者）。」。

示例输出（引用群 `123456` 中用户 `10001` 的消息，bot `20002` 是管理员）：

```text
撤回调试
目标消息：123456789（发送者 10001）
群号：123456
机器人：20002（管理员（admin））
目标用户：10001（普通成员（member））
消息时间：2026-01-01 12:00:00（已发出 30 秒）
判定：机器人是管理员，可撤回除群主外成员的消息。
结论：可以撤回该消息。
```

若结论是「无法判定」，报告会追加「说明：无法确认时会交由协议端最终校验。」；若目标消息没有解析到平台消息 ID，则给出「结论：无法撤回该消息。」。

## LLM 工具 `recall_message`

在 `[rules] enable_llm_tool = true`（默认）时注册为 LLM 工具。

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `message_id` | string | 否 | `""` | 要撤回的消息 ID：QQ 平台消息 ID（支持负数）或宿主内部消息 ID；留空时尝试从引用消息中取 |

调用时机：仅在用户明确要求撤回/删除某条消息时调用，不要主动撤回。

- 目标确定顺序：`message_id` → 触发消息的引用段 → 当前流最近人类消息的引用段。
- 发起者从当前流最近 10 分钟内最新的一条人类消息恢复（跳过 bot 自己、通知与命令消息）；插件不采信 LLM 传入的 `user_id`、`is_local_operator`、`platform`，平台按该消息的平台判定（默认 QQ）。恢复不到发起者时按无权限拒绝。同一会话多人连续发言时，权限会按最近一条人类消息推断，可能归到最近发言者。
- 与 `/撤回` 共用普通用户开关、会话作用域、bot 群身份判定与冷却；入口权限的差异见「权限规则」。
- 返回 dict：`content` 为结果说明或失败原因，可直接转述给用户；`success` 仅在协议端明确成功时为 `true`；`error` 成功时为空字符串，失败时与 `content` 为同一原因。`status=async` 时 `success=false`，`content` 为「撤回请求已提交处理，是否成功待确认。」。
- 运行期若 `enable_llm_tool` 已改为关闭但插件尚未重载，处理器返回「LLM 撤回工具已关闭。」。

```json
{"content": "已撤回该消息。", "success": true, "error": ""}
{"content": "机器人是管理员，不能撤回群主发送的消息。", "success": false, "error": "机器人是管理员，不能撤回群主发送的消息。"}
```

## 权限规则

### 入口权限

| 触发者 | `/撤回` | `/撤回调试` | `recall_message` |
|---|---|---|---|
| 宿主 `plugin.permission` 或 `[rules] admin_users` 中的用户 | ✅ | ✅ | ✅（需能恢复发起者） |
| 本地控制台 / CLI（`bot_console` / `maisaka_cli` 平台，或平台为空/QQ 且带 `is_local_operator`） | ✅ | ✅ | ⚠️ 不继承该标记；按恢复消息的平台与管理员名单判定 |
| 普通用户 | 开关允许时可撤回本会话内 bot/自己的消息 | ❌ | 同 `/撤回` |
| 其他平台（非 QQ、非控制台/CLI） | ❌ | ❌ | ❌ |

- 平台检查先于管理员名单：平台非空且不属于 `qq`、`bot_console`、`maisaka_cli` 时直接拒绝，不继承 QQ 管理员身份。
- `/撤回` 与 `/撤回调试` 直接使用宿主传入的 `is_local_operator`；`recall_message` 会剔除 LLM 可伪造的身份字段，因此本地控制台调用工具不会仅因“来自控制台”而放行。

### 管理员与普通用户

- 管理员 = 宿主 `plugin.permission` ∪ 插件 `[rules] admin_users`，按纯数字 ID 去重（`qq:10001` 与 `10001` 视为同一人）；非数字条目会被忽略。宿主名单读取失败时只使用 `admin_users`；两者都为空则没有管理员，本地控制台/CLI 命令仍可用，普通用户仍按自己的开关判断（不会因名单为空而全部放行）。
- `users_can_recall_bot_messages` / `users_can_recall_own_messages` 默认均为 `false`；不开启时普通用户会被拒绝，管理员不受这两个开关限制。
- 开启后，普通用户也只能撤回本会话内的目标：目标是 bot 自己 → 需要 `users_can_recall_bot_messages`；目标是发起者自己 → 需要 `users_can_recall_own_messages`；撤回他人消息一律拒绝。
- 会话作用域：群聊要求目标群号与触发群一致；私聊要求宿主消息库能查到该消息，且其会话流与当前 `stream_id` 相同；查不到归属一律拒绝。
- 开关只决定入口；实际删除仍受 bot 群身份限制。例如 bot 是普通成员时，普通用户撤回 bot 自己的消息只可能在时限内成功；撤回自己的消息会被群身份规则拒绝，撤回他人消息会在入口权限处被拒绝。管理员不受开关与会话作用域限制，但仍受 bot 在目标群的平台身份约束。

### 机器人平台能力（QQ 群身份）

进入撤回流程后，插件按 bot 的 QQ 群身份和目标发送者的身份判断平台能力；群身份通过 `get_group_member_info`（`no_cache=True`）实时查询，bot 账号通过 `get_login_info` 获取（失败时回退消息里的 `self_id`）。

| bot 群身份 | 目标发送者 | 能否撤回 |
|---|---|---|
| 群主 | 任何人 | ✅ 群内任何消息 |
| 管理员 | bot 自己、管理员、普通成员 | ✅ |
| 管理员 | 群主 | ❌ 管理员不能撤回群主消息 |
| 管理员 | 无法确认身份 | ⚠️ 交协议端校验 |
| 普通成员 | bot 自己，且未达时限 | ✅ |
| 普通成员 | bot 自己，已达时限 | ❌ |
| 普通成员 | 他人 | ❌ |
| 无法确认 bot 群身份 | 任意 | ⚠️ 交协议端校验 |
| 私聊 | bot 自己，且未达时限 | ✅ |
| 私聊 | bot 自己已达时限 / 对方 | ❌ |
| 私聊 | bot 账号未知 | ⚠️ 交协议端校验 |

- 时限由 `self_recall_time_limit_sec` 控制，默认 `120` 秒；判定使用 `>=`，消息发出达到时限即拒绝。群主/管理员撤回其有权限的消息不受该时限限制。
- 无法读取消息时间、无法查询 bot/目标群身份或无法确认 bot 账号时，判定为 `unknown`，不直接拒绝，仍调用协议端；实际能否撤回以协议端结果为准。
- 目标消息没有群号（`group_id` 为空、`"0"`、`"none"`、`"null"`）时默认按私聊处理；若消息记录明确标记为群聊但群号缺失，则按群身份未知交协议端校验，不按私聊直接拒绝。

## 安全边界

- 实际删除只有两个入口：`/撤回` 与 `recall_message`；`/撤回调试` 只读，不调用 `delete_msg`。
- 能撤回的上限由 bot 平台身份决定：群主可撤群内任何消息；管理员可撤除群主外的消息；普通成员只能撤自己时限内的消息；私聊只能撤 bot 自己时限内的消息。
- `/撤回` 与 `recall_message` 没有二次确认，显式 ID 会直接触发删除；操作前确认目标消息。
- 预判只用于提前解释原因，不能授予平台权限；最终能否撤回由协议端决定。
- 普通用户默认没有撤回权限；开启开关后也仅限本会话内 bot 自己的消息/自己的消息，且仍受 bot 群身份限制。管理员可以跨会话撤回，但同样受 bot 在目标群的平台身份限制；管理员名单为空时不会放行所有用户。
- 非 QQ 的聊天平台不支持（平台为 `bot_console` / `maisaka_cli` 的本地控制台/CLI 除外）：即使数字 ID 与 QQ 管理员相同，也不会继承 QQ 管理员身份。
- `status=async` 只表示请求已受理，不视为成功；协议端原始错误只写入日志，聊天中只显示分类原因。
- 开启 `enable_llm_tool` 会把撤回能力暴露给模型；不需要模型主动撤回时，将其设为 `false` 并重载插件。撤回操作（目标、发起者、结果）会写入插件日志；`cooldown_sec` 只限制同一会话的频率，不是全局配额。

## 失败原因与故障排查

### 入口与作用域

| 场景 | 返回 |
|---|---|
| `/撤回` 未引用消息且未给 ID | 请先引用一条消息再使用「/撤回」，或在命令后面附上消息 ID。 |
| 普通用户使用 `/撤回调试` | 仅 MaiBot 管理员或插件设置的管理员可以使用该指令。 |
| 普通用户撤 bot 消息，开关关闭 | 未开启普通用户撤回机器人消息，只有管理员可以撤回。 |
| 普通用户撤自己的消息，开关关闭 | 未开启普通用户撤回自己的消息，只有管理员可以撤回。 |
| 普通用户撤他人消息，或非 QQ 平台/无法确认发起者 | 普通用户只能撤回自己的消息（或按配置撤回机器人消息），不能撤回他人的消息。 |
| 普通用户撤其他会话的消息 | 这条消息不属于当前会话，只能撤回本会话内的消息。 |
| 同一会话冷却中 | 操作太频繁了，请稍等片刻再试。 |
| 工具已关闭但处理器仍被调用 | LLM 撤回工具已关闭。 |

### 群身份与时间窗

以下文案以 `self_recall_time_limit_sec = 120` 为例；修改该值后，文案中的「2 分钟」会按配置生成（整分钟显示「N 分钟」，否则显示「N 秒」）。

| 场景 | 返回 |
|---|---|
| bot 管理员撤群主消息 | 机器人是管理员，不能撤回群主发送的消息。 |
| bot 普通成员撤他人消息 | 机器人是普通成员，只能撤回自己 2 分钟内的消息，不能撤回对应身份（群主/管理员/普通成员/他人）发送的消息。 |
| bot 普通成员撤自己消息，已达时限 | 机器人是普通成员，只能撤回自己 2 分钟内的消息；该消息已发出超过 2 分钟，无法撤回。 |
| 私聊撤对方消息 | 私聊中没有群身份；机器人只能撤回自己 2 分钟内的消息，无法撤回对方的消息。 |
| 私聊撤自己消息，已达时限 | 私聊中机器人只能撤回自己 2 分钟内的消息；该消息已发出超过 2 分钟，无法撤回。 |

无法读取消息时间、无法确认 bot/目标群身份时不会直接返回失败，而是判定为无法确认，交协议端校验（`/撤回调试` 显示「无法判定」）。

### 消息查询与撤回

| 场景 | 返回 |
|---|---|
| 目标不存在/已撤回 | 没有找到这条消息，它可能不存在或已经被撤回了。 |
| 查询异常且无法分类 | 没有找到这条消息，或消息查询失败。 |
| 查询能力被拒 | 消息查询失败：能力调用被拒绝，请检查插件与适配器配置。 |
| 查询超时 | 消息查询失败：适配器响应超时，请稍后再试。 |
| 适配器/API 不可用 | 消息查询失败：适配器或 API 不可用，请确认适配器已安装并启用。 |
| 查询权限不足 | 消息查询失败：协议端拒绝查询（权限不足）。 |
| 撤回成功 | 已撤回该消息。 |
| `status=async` | 撤回请求已提交处理，是否成功待确认。 |
| 错误文案命中「过期/时间限制」 | 这条消息已经超出可撤回的时间范围，无法撤回了。 |
| 能力调用被拒 | 撤回接口调用失败：能力调用被拒绝，请检查插件与适配器配置。 |
| 撤回超时 | 撤回接口调用失败：适配器响应超时，请稍后再试。 |
| 适配器调用失败且无法归类（未安装/未配置/无法识别等） | 撤回接口调用失败，请确认平台适配器（如 Napcat 适配器）已安装并启用。 |
| 协议端权限拒绝（bot 是群主） | 机器人是群主，但协议端仍拒绝撤回，可能是消息类型或平台限制。 |
| 协议端权限拒绝（bot 是管理员，目标是群主） | 机器人是管理员，不能撤回群主发送的消息。 |
| 协议端权限拒绝（bot 是管理员，其他目标） | 机器人是管理员，但协议端仍拒绝撤回，可能超出平台限制或消息类型不支持。 |
| 协议端权限拒绝（撤回 bot 自己的消息） | 机器人似乎没有权限撤回这条消息，可能需要群管理员身份。 |
| 协议端权限拒绝（bot 身份未知） | 协议端拒绝了撤回，且无法确认机器人的群身份，请用「/撤回调试」检查。 |
| 其他协议端拒绝 | 撤回失败：协议端拒绝了这次撤回。 |

协议端响应 `status=ok` 或 `retcode=0` 才算成功。`status=async` 既可能来自协议端的结构化响应，也可能来自适配器异常文案：响应状态为 `async`，或错误文案中能明确识别出 `status=async` 时，按「待确认」处理；否则按协议端拒绝/失败处理。协议端原始错误只写入日志，不回到聊天。

### 排查

- **`/撤回` 没反应**：确认命令在消息末尾；`/撤回` 与 `/recall` 带斜杠，`撤回` 不带斜杠也可用。引用消息或改用 `/撤回 <消息ID>`；如果刚操作过，等待 `cooldown_sec` 冷却。
- **管理员身份不生效**：在宿主 `plugin.permission` 或插件 `[rules] admin_users` 中配置数字 ID（`qq:10001` 或 `10001` 均可）；非数字条目会被忽略。加载日志会显示最终管理员人数，为 0 时有警告。本地控制台/CLI 命令不受名单限制。
- **机器人是管理员/群主却撤不回**：先发 `/撤回调试`。常见原因是目标是群主消息（管理员不能撤回）、bot 只是普通成员、消息已超出时限，或群身份查询失败。确认适配器的 `get_group_member_info` 可用。
- **普通用户仍不能撤回**：两个开关默认关闭；开启后也只能撤回本会话内 bot 自己的消息/自己的消息，且 bot 需要有相应群身份。私聊还需宿主消息库能查到目标消息并匹配当前会话。
- **提示「撤回接口调用失败」**：检查 `[adapter] action_api` 是否指向实际适配器的通用 action 入口，适配器是否启用，以及是否支持 `delete_msg`、`get_msg`、`get_group_member_info`、`get_login_info`。提示能力被拒时，确认 `_manifest.json` 仍声明「安装与启用」一节列出的能力，且插件文件未被改动。
- **LLM 工具不出现**：确认 `[rules] enable_llm_tool = true` 并重载插件；热更新关闭后工具可能仍被调用，处理器会返回「LLM 撤回工具已关闭。」。日志可搜索「麦麦撤回」或 `recall`。
