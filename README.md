# 麦麦撤回（maimai-recall）

为 MaiBot 机器人提供**消息撤回**能力：

- **LLM 工具 `recall_message`**：让机器人撤回指定消息；撤回前先比较 bot 与目标发送者的 QQ 群身份，无法撤回时把确切原因返回给 bot。是否注册该工具由 `[rules] enable_llm_tool` 控制（默认开启）。
- **命令 `/撤回`**：引用（回复）一条消息后发送 `/撤回`，机器人尝试撤回被引用的那条消息；也支持 `/撤回 <消息ID>` 直接指定。
- **命令 `/撤回调试`**：输出机器人与目标用户的 QQ 群身份，并判断机器人能否撤回目标消息，用于排查“机器人明明是管理员却撤不回”的问题；只读，不执行删除。

**实际删除可通过 `/撤回` 或 `recall_message` 工具执行**，两者共用同一套权限：MaiBot 管理员或插件设置的管理员始终可用；普通用户默认不可用，开启 `users_can_recall_bot_messages` / `users_can_recall_own_messages` 后可分别撤回**本会话内**机器人自己的消息/自己发出的消息。`/撤回调试` 仅管理员可用且只读。

撤回动作通过平台适配器的通用 action 接口转发给协议端执行。权限检查按 **bot 的 QQ 群身份** 与目标发送者身份判定，再调用协议端撤回。

## 安装

1. 把 `cateye_maimai_recall/` 整个目录放进 MaiBot 安装目录的 `plugins/` 下。
2. 启动/重启 MaiBot（`run.bat` / `bot.py`），日志出现「麦麦撤回已加载」即加载成功。
3. 在 WebUI（`http://127.0.0.1:8001`）插件管理中确认插件已启用，或在插件 `config.toml` 的 `[plugin]` 节设置 `enabled = true`。

> 本插件通过适配器的通用 action 接口（默认 `adapter.napcat.action.call`）执行撤回与群成员身份查询：MaiBot 1.2.x 请安装 **Napcat 适配器**（`maibot-team.napcat-adapter`）；1.3.0 起 Napcat 已合并进 **SnowLuma 适配器**（`maibot-team.snowluma-adapter`），API 名不变。请确认对应适配器已安装并启用。使用其他适配器时，把配置里的 action API 名改成对应适配器的通用 action 入口，并确认其支持 `get_msg`、`delete_msg`、`get_group_member_info`、`get_login_info`。

## 配置

运行时 `config.toml` 由 Runner 在插件目录下自动生成（不要提交进仓库），主要配置项：

| 配置节 | 字段 | 默认 | 说明 |
|---|---|---|---|
| `[rules]` | `admin_users` | `[]` | 可选：插件管理员 ID 列表；留空自动跟随宿主 `plugin.permission`，填写后与宿主名单合并并按纯 ID 去重 |
| `[rules]` | `enable_llm_tool` | `true` | 是否注册 `recall_message` LLM 工具；关闭后不再注册（重载插件生效，热更新期间运行时也会拒绝调用） |
| `[rules]` | `users_can_recall_bot_messages` | `false` | 允许普通用户撤回**本会话内**机器人自己发出的消息（仍受 bot 群身份与 2 分钟时限约束） |
| `[rules]` | `users_can_recall_own_messages` | `false` | 允许普通用户撤回**本会话内**自己发出的消息（需要机器人具备群主/管理员身份，仍受 bot 群身份限制） |
| `[rules]` | `self_recall_time_limit_sec` | `120` | 机器人以**普通成员**身份撤回自己消息的时间限制（秒）；机器人是群主/管理员时不受限 |
| `[adapter]` | `action_api` | `adapter.napcat.action.call` | 适配器通用 action 调用 API 名，撤回、消息查询与群身份查询都通过它转发 |
| `[limits]` | `cooldown_sec` | `10` | 同一会话两次撤回操作之间的最小间隔（秒），`0` 表示不限制 |

**普通用户开关默认均关闭**：不开启时，非管理员使用 `/撤回` 或 `recall_message` 会被拒绝；开启后也只允许撤回本会话内的机器人消息/自己的消息，跨群/跨私聊仍会被拒绝。管理员始终不受这两个开关限制。

**管理员来源**：宿主 `plugin.permission` 与插件 `admin_users` 的并集，按纯 ID 去重（`qq:10001` 与 `10001` 视为同一人）。宿主名单读取失败时只保留显式配置的插件管理员；两者都为空则无管理员（普通聊天用户一律拒绝，本地控制台除外）。

修改 `config.toml` 保存即可热重载，无需重启。

## 使用方法

> `/撤回` 与 `recall_message` 工具共用同一套权限：默认仅 MaiBot 管理员或插件设置的管理员可用；开启对应开关后，普通用户也可在本会话内撤回机器人自己的消息/自己的消息。`/撤回调试` 始终仅管理员可用且只读。

### 命令 `/撤回`

1. **引用（回复）**想撤回的那条消息，发送 `/撤回`（或直接发送 `撤回`）；
2. 或者发送 `/撤回 <消息ID>` 直接指定平台消息 ID（支持负数 ID）。

命令执行后机器人会把结果（成功或失败原因）发到当前会话。

### 命令 `/撤回调试`

用于排查“机器人是群管理员/群主却撤不回消息”：

- **引用一条消息**发送 `/撤回调试`（或 `/撤回debug`、`/recall_debug`）：以被引用消息的发送者作为目标用户，显示其在目标群的 QQ 身份；
- **不引用消息**直接发送：以命令发送者作为目标用户，显示其在当前群的 QQ 身份；
- 也可以用 `/撤回调试 <消息ID>` 指定目标消息。

机器人会输出群号、机器人身份、目标用户身份、消息时间，以及按“群主可撤任何消息 / 管理员不能撤群主消息 / 普通成员只能撤自己 2 分钟内的消息”比较后的结论。该命令只做查询和判断，不会真的撤回消息。

### LLM 工具 `recall_message`

机器人可以调用该工具**实际撤回**指定消息，参数：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `message_id` | string | 否 | 要撤回的平台消息 ID（QQ 消息 ID，可能是负数）；当用户引用了某条消息时留空，插件会尝试取被引用消息的 ID |

- 该工具受 `[rules] enable_llm_tool` 控制（默认开启）；关闭后不再注册，热更新期间运行时也会拒绝调用。
- 撤回前会走与 `/撤回调试` 相同的能力链路：解析目标 → 查询 bot 与目标发送者的 QQ 群身份 → 按群主/管理员/普通成员规则比较 → 通过后才调用 `delete_msg`。
- 发起者权限与 `/撤回` 一致：管理员始终可用；普通用户仅在对应开关开启且目标属于本会话内机器人/自己的消息时可用。
- 无法撤回时不执行删除，`success=false`，`content` 返回确切原因，可直接由机器人转述给用户。

## 权限规则

### 入口权限

| 触发者 | `/撤回` | `/撤回调试` | `recall_message` 工具（`enable_llm_tool=true` 时注册） |
|---|---|---|---|
| 宿主 `plugin.permission` 内用户 | ✅ | ✅ | ✅ |
| 插件 `admin_users` 内用户 | ✅ | ✅ | ✅ |
| 本地控制台 / CLI（`is_local_operator`，或 `bot_console` / `maisaka_cli` 平台） | ✅ | ✅ | ✅ |
| 普通用户 | ⚙️ 仅当开启对应开关时，可撤回**本会话内**机器人消息/自己的消息 | ❌ 直接拒绝 | ⚙️ 与 `/撤回` 相同 |
| 非 QQ 平台（即使数字 ID 与 QQ 管理员相同） | ❌ 不继承 QQ 管理员 | ❌ | ❌ 不继承 QQ 管理员 |

> `/撤回` 与 `recall_message` 共用发起者权限、普通用户开关、会话作用域与 bot 群身份判定；`/撤回调试` 只读且仅管理员可用。非管理员的拒绝提示受冷却限制，避免刷指令。

### 机器人平台能力（QQ 群身份）

通过发起者权限（管理员，或开关允许的普通用户且目标在本会话内）后，实际撤回由机器人账号执行，因此还受 **bot 的 QQ 群身份**与目标发送者身份的约束：

| 机器人身份 | 目标消息发送者 | 是否可撤回 |
|---|---|---|
| 群主 | 群内任何人（含管理员、自己） | ✅ 任何消息 |
| 管理员 | 普通成员、管理员、自己 | ✅ |
| 管理员 | 群主 | ❌ 管理员不能撤回群主的消息 |
| 普通成员 | 自己 | ✅ 仅限 2 分钟内（`self_recall_time_limit_sec`） |
| 普通成员 | 其他人（群主/管理员/普通成员） | ❌ 无权限 |
| 查询不到群身份 | 任意 | ⚠️ 无法预判，交由协议端最终校验 |
| 私聊（无群身份） | 机器人自己 | ✅ 仅限 2 分钟内 |
| 私聊（无群身份） | 对方 | ❌ 无权限 |

示例：

- 机器人是**管理员**，目标是**群主**的消息 → 「机器人是管理员，不能撤回群主发送的消息。」
- 机器人是**普通成员**，目标是**管理员**的消息 → 「机器人是普通成员，只能撤回自己 2 分钟内的消息，不能撤回管理员发送的消息。」
- 机器人是**普通成员**，撤回自己**超过 2 分钟**的消息 → 「机器人是普通成员，只能撤回自己 2 分钟内的消息；该消息已发出超过 2 分钟，无法撤回。」
- **私聊**中撤回对方消息 → 「私聊中没有群身份；机器人只能撤回自己 2 分钟内的消息，无法撤回对方的消息。」

## 安全边界

- **实际删除入口**：`/撤回` 与 `recall_message` 工具会调用 `delete_msg`，两者共用管理员/普通用户开关/会话作用域/bot 群身份判定；`/撤回调试` 只读。管理员始终可用；普通用户默认不可用，开启 `users_can_recall_bot_messages` / `users_can_recall_own_messages` 后可分别撤回本会话内机器人自己的消息/自己发出的消息。
- **LLM 工具开关**：`[rules] enable_llm_tool` 默认 `true`；关闭后 `get_components()` 不再返回 `recall_message`（重载插件生效）。热更新场景下工具若仍被调用，处理器会返回“LLM 撤回工具已关闭”。
- **Tool 发起者判定**：群聊 Tool 上下文不携带当前发送者，插件从当前流最近 10 分钟内最新的人类消息恢复发起者，并用该消息校准 stream_id/group_id；恢复失败按无权限处理。插件不采信 LLM 传入的 `user_id` / `is_local_operator` / `platform`，平台按恢复消息的平台判定（默认 QQ），非 QQ 直接拒绝。
- **普通用户开关与会话作用域**：两个开关默认均为 `false`；开启后普通用户也只能撤回**当前会话内**的目标——群聊要求目标群号与触发群一致，私聊要求目标消息同属当前会话流，归属查询不到时一律拒绝（fail-closed）。管理员不受开关与会话作用域限制。
- **管理员来源**：宿主 `plugin.permission` ∪ 插件 `admin_users`，按纯 ID 去重。宿主读取失败时只保留显式配置的插件管理员；两者都为空则无管理员，绝不放行所有用户。本地控制台的 `is_local_operator` 标记与 `bot_console` / `maisaka_cli` 平台仍由宿主注入并天然放行。
- **群身份能力**：撤回前按 bot 的 QQ 群身份与目标发送者身份预判平台能力；查询失败时只做提示，最终由协议端校验，不会因查询失败而绕过发起者权限校验。
- **群聊/私聊严格区分**：目标消息 `group_id` 为空、`"0"`、`"none"`、`"null"` 时按私聊规则判定；若数据库明确标记该消息属于群聊但群号缺失，则按“群身份未知”交协议端校验，不会按私聊规则直接拒绝。有有效群号时按 QQ 群身份规则判定。
- **适配器错误分类**：官方 Napcat/SnowLuma 的 `action.call` 在非 ok 时会抛异常，插件会从异常文案中识别能力拒绝、权限拒绝、消息不存在、超时与可识别的 `status=async`，再翻译成对应原因，不再一律报“适配器未安装”。官方适配器若不返回 `status=async` 文案，会按协议端拒绝/失败处理。
- **频控**：同一会话两次撤回操作之间有冷却间隔（`[limits] cooldown_sec`，默认 10 秒）；非管理员的拒绝提示也使用独立冷却，避免刷指令。

## 失败原因一览

| 场景 | 机器人回复 |
|---|---|
| 普通用户使用 `/撤回调试` | 仅 MaiBot 管理员或插件设置的管理员可以使用该指令。 |
| 普通用户撤机器人消息，但开关关闭 | 未开启普通用户撤回机器人消息，只有管理员可以撤回。 |
| 普通用户撤自己的消息，但开关关闭 | 未开启普通用户撤回自己的消息，只有管理员可以撤回。 |
| 普通用户撤他人的消息 | 普通用户只能撤回自己的消息（或按配置撤回机器人消息），不能撤回他人的消息。 |
| 普通用户撤其他会话的消息 | 这条消息不属于当前会话，只能撤回本会话内的消息。 |
| 工具无法撤回 | 返回对应原因且不执行删除（如无权限、超过两分钟、消息不存在等）。 |
| 工具开关关闭 | LLM 撤回工具已关闭。 |
| 机器人是管理员却要撤回群主消息 | 机器人是管理员，不能撤回群主发送的消息。 |
| 机器人是普通成员却要撤回他人消息 | 机器人是普通成员，只能撤回自己 2 分钟内的消息，不能撤回管理员/群主/普通成员发送的消息。 |
| 机器人是普通成员撤回自己超时消息 | 机器人是普通成员，只能撤回自己 2 分钟内的消息；该消息已发出超过 2 分钟，无法撤回。 |
| 私聊中撤回对方消息 | 私聊中没有群身份；机器人只能撤回自己 2 分钟内的消息，无法撤回对方的消息。 |
| 私聊中机器人自己的消息超时 | 私聊中机器人只能撤回自己 2 分钟内的消息；该消息已发出超过 2 分钟，无法撤回。 |
| 消息不存在 / 已撤回 / 查询失败 | 没有找到这条消息，或消息查询失败。 |
| 操作过于频繁（同一会话冷却中） | 操作太频繁了，请稍等片刻再试。 |
| 协议端返回可识别的 `status=async` | 撤回请求已提交处理，是否成功待确认（官方适配器若不返回该状态，按协议端拒绝/失败处理）。 |
| 适配器未安装 / 能力被拒 | 撤回接口调用失败，请确认平台适配器已安装并启用，或检查能力声明。 |
| 其他协议端权限拒绝 | 按 bot 与目标发送者群身份翻译，例如“机器人是管理员，但协议端仍拒绝撤回，可能超出平台限制或消息类型不支持。” |
| 其他协议端错误 | 撤回失败：协议端拒绝了这次撤回。（原始错误只写入日志，不回显到聊天） |

## 常见问题（故障排查）

- **报 `E_CAPABILITY_DENIED`**：本插件需要的能力已在 `_manifest.json` 声明（`send.text`、`api.call`、`message.get_by_id`、`message.get_recent`、`config.get`）。如果修改过 manifest，需要完整重启 MaiBot（manifest 变更不做热重载）。
- **提示"撤回接口调用失败"**：检查 Napcat 适配器是否安装并启用（`[plugin] enabled = true`），或修改 `[adapter] action_api` 指向实际使用的适配器通用 action 入口。
- **引用消息后 `/撤回` 不触发**：命令按 `(?i)(?<!\S)(?:/?撤回|/recall)(?:\s+消息ID)?\s*$` 匹配消息末尾（支持 `/撤回 <消息ID>` 的显式 ID）。若某些客户端引用预览与命令文本之间没有空格导致不触发，可改用 `/撤回 <消息ID>` 的形式。
- **机器人是管理员/群主却撤不回**：先发送 `/撤回调试`（引用目标消息或不引用）查看双方群身份。常见原因是目标是群主消息（管理员不能撤回）或机器人只是普通成员。插件会直接给出对应原因；若结论为“无法判定”，检查适配器 `get_group_member_info` 是否可用。
- **管理员身份不生效**：确认宿主主配置 `[plugin] permission` 中填写了你的账号（如 `"qq:123456789"`），或在插件 `[rules] admin_users` 中显式配置；两处会合并去重。
- **普通用户无法使用 `/撤回`**：默认两个开关均为关闭；在插件配置中开启 `users_can_recall_bot_messages` / `users_can_recall_own_messages` 后，普通用户可分别撤回本会话内机器人自己的消息/自己的消息。`/撤回调试` 始终仅管理员可用。
- **普通用户开启开关后仍撤不回**：检查目标是否在本会话内、是否是机器人/自己的消息，以及 bot 的群身份是否允许（例如 bot 是普通成员时不能撤回他人消息；bot 是管理员时不能撤回群主消息）。
- **如何关闭 LLM 撤回工具**：把 `[rules] enable_llm_tool` 设为 `false` 并重载插件；之后 `recall_message` 不再注册。热更新后工具若仍被调用，会返回“LLM 撤回工具已关闭”。
- **查看日志**：插件日志经 Runner 自动转发到主进程日志（`logs/`），搜索「麦麦撤回」或 `recall` 即可。

## 测试方式

1. **命令测试**：管理员引用一条机器人刚发出的消息发送 `/撤回` → 应回复撤回结果；普通用户默认发送 `/撤回` → 应回复未开启开关/无权限。
2. **普通用户开关**：开启 `users_can_recall_bot_messages` 后，普通用户应能撤回本会话内机器人消息；开启 `users_can_recall_own_messages` 后，应能撤回本会话内自己的消息；跨群/跨私聊仍应被拒绝。
3. **调试命令**：管理员在群里发送 `/撤回调试`，确认输出机器人与自己的群身份及结论；引用一条群主/管理员/普通成员的消息再发送，确认目标用户身份与能否撤回的结论随之变化。
4. **Tool 撤回**：让机器人调用 `recall_message`，确认撤回前先按 bot/目标群身份判定；无权限时不删除并返回原因；关闭 `enable_llm_tool` 后确认工具不再注册。
5. **能力边界**：把机器人分别设为群主/管理员/普通成员，测试撤回群主、管理员、普通成员消息，以及撤回 2 分钟前后的自身消息。
6. **私聊测试**：私聊中撤回机器人自己的近期消息应成功；撤回对方消息、撤回超过 2 分钟的自身消息应回复对应原因。
7. **异常路径**：消息不存在、协议端权限拒绝、适配器未启用/能力被拒时，确认回复不是笼统的“适配器未安装”。
8. **配置热重载**：修改 `config.toml` 保存，日志出现「麦麦撤回配置已热更新」。
9. **卸载测试**：在 WebUI 停用插件，确认日志出现「麦麦撤回已卸载」。
