# 麦麦撤回（maimai-recall）

为 MaiBot 机器人提供**消息撤回**能力：

- **LLM 工具 `recall_message`**：传入指定消息 ID，让机器人撤回那条消息；失败时返回具体原因（权限不足、消息发出超过两分钟、消息不存在等），由机器人转述给用户。
- **命令 `/撤回`**：引用（回复）一条消息后发送 `/撤回`，机器人尝试撤回被引用的那条消息；也支持 `/撤回 <消息ID>` 直接指定。

撤回动作通过平台适配器的通用 action 接口转发给协议端执行，插件侧负责权限与时间限制判定，并把协议端返回的错误翻译成可读的失败原因。

## 安装

1. 把 `cateye_maimai_recall/` 整个目录放进 MaiBot 安装目录的 `plugins/` 下。
2. 启动/重启 MaiBot（`run.bat` / `bot.py`），日志出现「麦麦撤回已加载」即加载成功。
3. 在 WebUI（`http://127.0.0.1:8001`）插件管理中确认插件已启用，或在插件 `config.toml` 的 `[plugin]` 节设置 `enabled = true`。

> 本插件默认通过 **Napcat 适配器**（`maibot-team.napcat-adapter`）执行撤回，请确认已安装并启用该适配器。使用其他适配器时，把配置里的 action API 名改成对应适配器的通用 action 入口即可。

## 配置

运行时 `config.toml` 由 Runner 在插件目录下自动生成（不要提交进仓库），主要配置项：

| 配置节 | 字段 | 默认 | 说明 |
|---|---|---|---|
| `[rules]` | `admin_users` | `[]` | 管理员用户 ID 列表，可撤回任何消息；支持 `"123456"` 或 `"qq:123456"` 两种写法 |
| `[rules]` | `users_can_recall_bot_messages` | `true` | 允许普通用户让机器人撤回机器人自己发出的消息（仍受时间限制） |
| `[rules]` | `users_can_recall_own_messages` | `false` | 允许普通用户撤回自己发的消息（需要机器人具备群管理员身份，否则协议端会拒绝） |
| `[rules]` | `self_recall_time_limit_sec` | `120` | 机器人撤回自己消息的时间限制（秒）；QQ 平台限制为 2 分钟，机器人是群管理员/群主时不受限 |
| `[adapter]` | `action_api` | `adapter.napcat.action.call` | 适配器通用 action 调用 API 名，撤回与消息查询都通过它转发 |

修改 `config.toml` 保存即可热重载，无需重启。

## 使用方法

### 命令 `/撤回`

1. **引用（回复）**想撤回的那条消息，发送 `/撤回`（或直接发送 `撤回`）；
2. 或者发送 `/撤回 <消息ID>` 直接指定平台消息 ID（支持负数 ID）。

命令执行后机器人会把结果（成功或失败原因）发到当前会话。

### LLM 工具 `recall_message`

机器人可以在对话中自主调用该工具撤回消息，参数：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `message_id` | string | 否 | 要撤回的平台消息 ID（QQ 消息 ID，可能是负数）；当用户引用了某条消息要求撤回但没给 ID 时可留空，插件会自动撤回被引用的消息 |

仅在用户明确要求撤回/删除消息时才会调用，不会主动撤回。

## 权限规则

| 触发者 | 目标消息 | 是否允许 |
|---|---|---|
| 管理员（`admin_users` 内，或本地控制台） | 任何消息 | ✅ |
| 普通用户 | 机器人自己发的消息 | ✅（`users_can_recall_bot_messages=true`，默认开） |
| 普通用户 | 自己发的消息 | ⚙️（`users_can_recall_own_messages`，默认关） |
| 普通用户 | 其他人的消息 | ❌ |

## 失败原因一览

| 场景 | 机器人回复 |
|---|---|
| 非管理员撤回他人的消息 | 你不是管理员，不能撤回他人的消息。 |
| 机器人自己的消息超过时限（非群管理员时） | 这条消息已经发出超过 2 分钟，无法撤回了。 |
| 消息不存在 / 已被撤回 | 没有找到这条消息，它可能不存在或已经被撤回了。 |
| 机器人不是群管理员却要撤回他人消息 | 机器人不是群管理员，无法撤回他人的消息。 |
| 适配器未安装 / 未启用 | 撤回接口调用失败：……请确认平台适配器已安装并启用。 |
| 其他协议端错误 | 撤回失败：<协议端返回的原始信息> |

## 常见问题（故障排查）

- **报 `E_CAPABILITY_DENIED`**：本插件需要的能力已在 `_manifest.json` 声明（`send.text`、`api.call`、`message.get_by_id`）。如果修改过 manifest，需要完整重启 MaiBot（manifest 变更不做热重载）。
- **提示"撤回接口调用失败"**：检查 Napcat 适配器是否安装并启用（`[plugin] enabled = true`），或修改 `[adapter] action_api` 指向实际使用的适配器通用 action 入口。
- **引用消息后 `/撤回` 不触发**：命令按 `(?<!\S)(?:/?撤回|/recall)$` 匹配消息末尾。若某些客户端引用预览与命令文本之间没有空格导致不触发，可改用 `/撤回 <消息ID>` 的形式。
- **撤回他人消息一直失败**：需要在群里把机器人设为群管理员；QQ 平台只有群管理员/群主能撤回成员消息。
- **查看日志**：插件日志经 Runner 自动转发到主进程日志（`logs/`），搜索「麦麦撤回」或 `recall` 即可。

## 测试方式

1. **命令测试**：引用一条机器人刚发出的消息发送 `/撤回` → 应回复「已撤回该消息。」；引用一条他人消息（非管理员）发送 `/撤回` → 应回复权限原因。
2. **Tool 测试**：在聊天里对机器人说"撤回消息 ID xxx"或引用消息说"帮我撤回这条"，观察日志 `Tool recall_message` 与 `plugin.invoke_tool`。
3. **配置热重载**：修改 `config.toml` 保存，日志出现「麦麦撤回配置已热更新」。
4. **卸载测试**：在 WebUI 停用插件，确认日志出现「麦麦撤回已卸载」。
